## Decisions made

- **Scheduler lives in the dispatcher** (asyncio loop, 30s checks), not the
  planned `mission-automations.timer`: the dispatcher must be running for
  tasks to execute anyway, an in-process loop needs no new unit, has no boot
  race, and past-due `next_run_at` gives systemd-Persistent-style catch-up
  for free. Advance-before-submit prevents tight-looping on submit failure.
- **Gate scope**: notify gate applies to `done` results from sources
  `automation` + `timer`; failures keep their existing speakable-error path.
  Meta task types (reflection, memory-consolidate, notify-gate,
  automation-parse) are never announced at all — this also fixes the
  pre-existing noise where jarvis's notices loop spoke "Done: …" for every
  agentic completion including reflections.
- **Fail-open**: a broken gate notifies with a generic summary; the user
  asked to be told, silence is the worse failure.
- Internal quick sources (`automation`, `automation-parse`, `notify-gate`)
  excluded from quick-session continuity (session-11 lesson about meta-work
  contaminating conversational machinery); the gate resumes via metadata
  `resume_session_id`, now honored by stream_quick ahead of per-source
  continuity.
- NL divert is conservative: schedule-phrase regex AND question-opener veto,
  mode=auto only, config-switchable (`nl_detect`). A missed divert is just a
  normal task; a false divert would be an unwanted automation.
- Empty/absent `automations:` config block disables the whole feature —
  that's what keeps the unit suite hermetic (no LLM calls from tests).
