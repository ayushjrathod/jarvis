## Crash-class bugs (voice service)

- `httpx.StreamClosed` is a RuntimeError, NOT `httpx.HTTPError` (verified,
  httpx 0.28.1) — the session-7 barge-in crash fix (jarvis/main.py catches
  HTTPError only) has a residual timing window: brain.cancel() closes the
  response mid-iteration → StreamClosed → uncaught → wake_loop dies →
  gather kills the process.
- Audio-output errors are uncaught on the whole speak path: a vanished
  sink (BT earphones!) → PortAudioError in Player.play → propagates through
  speak_sentences → handle_utterance → loop task → process exit. Restart
  loop with model reload each time.
- hotkey.py: device unplug → OSError in `dev.read()` → watcher thread dies
  silently; no-keyboards-at-start RuntimeError also dies in-thread. In
  mission-dictate that makes main exit **0**, so Restart=on-failure does
  NOT restart it → dictation dead until manual restart.
- Empty trigger string in any SKILL.md frontmatter → IndexError in
  areas._subsequence (verified) → every POST /task 500s.

## Degraded-mode bugs (dispatcher)

- stream_quick has no finally: client disconnect mid-SSE (jarvis killed,
  browser closed) skips finish_run/set_task_status → rows stuck 'running'.
- quick.py CLI backend: asyncio readline 64KB default limit — tool-enabled
  quick query that Reads a large file → ValueError → task failed. Also
  stderr=PIPE never drained during streaming → possible deadlock-till-
  timeout if the CLI spews to stderr.
- Queue watcher task is unsupervised — if watch() itself raises, queue
  ingestion silently stops while /health stays green.
- One malformed frontmatter file in vault/tasks/ → GET /vault/tasks 500 →
  whole Tasks widget dies. toggle_task on a file without `status:` no-ops.
- All sqlite calls are sync on the event loop (timeout=5) — a locked DB
  can stall every request/SSE stream up to 5s.
- cancel() vs finishing run race can overwrite 'cancelled' with 'failed'.

## Config/env tripwires

- Setting ANTHROPIC_API_KEY arms the never-executed messages_api path
  (untested beta kwargs, per-call AsyncAnthropic never closed);
  resolve_backend also treats ~/.config/anthropic/credentials existence as
  proof of creds, which the SDK doesn't actually read.
- wake_threshold 0.2 == the hardcoded near-miss log floor → tuning
  telemetry now empty band; false-wake risk in noise.
- Spoken wake acks play into the open capture mic on speakers → ack audio
  prefixes the utterance sent to STT (same echo class as barge-in caveat).
- mission-backup has no ordering vs dispatcher writes; sqlite3 .backup can
  hit "database is locked" (no busy timeout) — silent journal-only failure.

## Fixes implemented same session (user: "do what you feel is right")

All of the above except the deliberate skips (see below). Files touched:

- `dispatcher/db.py` — `reconcile_orphans()`: startup sweep fails any
  'queued'/'running' rows left by a dead process; wired into Service init.
- `dispatcher/service.py` — `stream_quick` wrapped in try/finally: client
  disconnect mid-SSE now settles task+run as 'cancelled' ("client
  disconnected mid-stream"); sync DB calls only in the finally (no awaits
  during GeneratorExit). Also a cancel-race guard in `_run_agentic_inner`
  so 'cancelled' isn't overwritten by 'failed'.
- `dispatcher/quick.py` — subprocess `limit=4MiB` (asyncio readline default
  is 64KiB; one Read tool result = one JSON line); stderr drained
  concurrently (deadlock-till-timeout risk); `resolve_backend` now trusts
  env vars only (the SDK never read the credentials file we probed);
  `AsyncAnthropic` used as an async context manager.
- `dispatcher/queue_watcher.py` — watch loop supervised: a bad scan logs
  and retries next poll instead of silently killing the unobserved task.
- `dispatcher/areas.py` — empty/non-string trigger phrases dropped at
  parse; `_subsequence` guards empty needles (the IndexError 500).
- `dispatcher/vault.py` — `list_tasks` skips unparseable files.
- `dispatcher/main.py` — `timeout_graceful_shutdown=5`: the always-open
  /events SSE streams were holding shutdown until systemd SIGKILLed the
  dispatcher after 90s — **that SIGKILL is what orphaned the 07-09 task**.
  Found live during deploy; restarts now take ~5s.
- `jarvis/main.py` — barge-in catch broadened to `httpx.StreamError`
  (verified NOT an HTTPError; residual crash window from session 7);
  playback/TTS errors contained in `speak_sentences` (BT sink loss drops
  the reply, not the service); `_handle_safely` wraps every interaction;
  `wake_loop` retries capture failures at 5s intervals (mic loss);
  `notices_loop` guards say(); barge monitor gets its own `threading.Event`
  stop flag so a stale watch thread can't kill the next utterance's audio.
- `jarvis/engines/brain_dispatcher.py` — notices reconnect also on
  StreamError.
- `jarvis/hotkey.py` — supervised: device loss drops that device and
  rescans (synthesizes on_release if a key was held); no-devices retries
  every 5s with the input-group hint instead of dying in-thread; callbacks
  wrapped. Thread now only exits via stop().
- `jarvis/dictate.py` — exits **nonzero** if the watcher dies (was exit 0,
  dodging Restart=on-failure); `type_text` reports missing
  ydotool/ydotoold instead of dying silently in the worker thread.
- `jarvis/engines/wake_openwakeword.py` — near-miss log band is now
  `[threshold*0.5, threshold)` (fixed 0.2 floor == current threshold had
  emptied it).
- `scripts/run_agent.py` — connection failures retried 12×5s; HTTP error
  responses NOT retried (server got the request; avoid duplicate tasks).
- `scripts/backup_db.sh` — `.timeout 5000` on the sqlite3 .backup.
- `scripts/doctor.sh` — checks `ydotool` unit name too (not just ydotoold).
- Tests: +6 (reconcile, stream_quick done+disconnect bookkeeping, vault
  tolerance, malformed triggers ×2) → **52 green**.
