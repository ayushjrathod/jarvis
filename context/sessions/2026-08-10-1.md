## Core (service/runner/queue/telemetry/quick)

- **The queue watcher submitted before claiming the file.** `OSError` is on the
  transient-retry whitelist and the `.processed` rename sat inside the same `try`,
  so a rename that failed (read-only mount, ENOSPC, a permission problem, a synced
  or FUSE queue dir) left the file in place and the next poll **ran the whole task
  again** — up to `max_retries` extra full agentic runs with their real side
  effects, and the log line never mentioned that a task had already been
  dispatched. Now: claim (`*.claimed`) → submit → file. Past the submit nothing may
  return the file to the queue; a failed *claim* leaves it untouched for a clean
  retry, and a failed *filing* logs loudly and leaves it claimed rather than
  re-running. Verified both directions, including that a claim failure dispatches
  nothing and leaves no stray file.
- **A wall-clock timeout was retried.** Wrong twice: a run that hit 600s was
  usually *working*, so the retry re-ran the same prompt with the same write
  grants over files the first attempt had already edited; and `_attempt` raises
  before any `result` event, so the timed-out attempt contributed no cost,
  session_id or steps while sharing the single runs row — up to 600s of real model
  work invisible to `/stats`. A spawn failure is transient; a timeout is a verdict.
  (The pre-existing test asserted the old behaviour; flipped deliberately, with the
  reasoning in the test body.)
- **`max_cost_usd: 0` became the full default cap** — `0 or 0.50` is 0.50, so the
  tightest possible request produced the loosest configured budget.
- **A barge-in's run row was overwritten with `failed`.** An HTTP quick task is
  never registered in `svc.bg`, so `cancel()` only kills the subprocess — after
  writing 'cancelled' — and the kill surfaces as EOF with no result event, i.e.
  `failed` + "claude exited -9". That clobbered the honest 'cancelled' on **every
  voice barge-in**. The task row was always right; the run row and its error
  string were not.
- **TTFT was fabricated for non-streamed runs.** When the CLI emits no incremental
  text, `quick.py` synthesizes one delta from the final result — so "time to first
  token" was the whole run duration, landing in `/stats` quick-latency averages
  looking exactly like a real measurement. `meta["streamed"]` now flows to
  `telemetry.stream_stats`, which omits the latency columns instead. Verified
  end-to-end: synthesized → `ttft_ms=None`, real stream → recorded.
- **Consolidation episodes were stranded on three paths.** They are marked
  consolidated at hand-off, and only `_run_agentic_inner` settling 'failed' rolled
  them back — leaving cancellation, the outer crash handler, and a restart mid-run
  (which `reconcile_orphans` settles as failed with no idea the task owned
  episodes). One `_rollback_episodes` helper now covers all of them, plus a startup
  sweep via `db.orphaned_consolidation_episode_ids()`.
- **`/memory/consolidate` was a read-then-mark race** — two callers (the 02:30
  timer and a manual POST) could both read the same unconsolidated set and both
  submit an agent run. Serialized with a flag; a second caller is told
  `already_running` rather than made to wait, because the first claimed everything.
- `quick_sessions` grew without bound (ask-screen uses a fresh source per
  screenshot, so entries were never revisited); now swept on every lookup.

## Voice

PTT thread now supervised (it could die while systemd reported `active (running)`);
a PTT press during the STT window is no longer erased by `player.resume()`;
`--mode both` can no longer answer one utterance twice (the busy predicate ignored
the recorder); `ydotool` has a timeout, so a wedged `ydotoold` can't kill dictation
permanently; the barge monitor no longer races itself on the shared VAD; notice
barge-in drops the backlog; stream leaks on a failed `start()`; `play_async` logs
instead of `pass`; per-fd key tracking so an unrelated keyboard unplugging can't
truncate a clip; `ptt_dictate.py` refuses to run (above the model load) while
staying readable as the reference CLAUDE.md keeps it for.

**The code-block leak is fixed** — I had demonstrated a 1029-char block producing
5 chunks of raw `rm -rf` shell; it now yields "Here is the script." / "code block
omitted." / "Run it carefully." The chunker is fence-aware, plus a whole-reply cap.

*Correction to my brief:* I suggested "cancel then await" for the monitor race.
That would not have worked — cancelling only detaches the `to_thread` future and
the await returns immediately while the worker thread runs on. Awaiting **without**
cancelling is what waits for the thread to leave the VAD.

## Memory

the prune set, so an onnxruntime upgrade breaking rapidocr would silently remove
every OCR'd document from search); one unreadable or non-UTF-8 `SKILL.md` **500'd

Verified behaviourally, not just by test count: a dep failure leaves the index
searchable; a corrupt SKILL.md still loads the good areas; a `notes-helper`
directory declaring `name: tasks` gets Bash stripped **while a genuinely blessed
`tasks` directory keeps it**.

*copy* of the live DB with all 76 episodes preserved.

## Ops

`TimeoutStartSec` on every oneshot unit, with each script's retry loop now capped
by **wall clock** as well as attempt count — an attempt count is not a budget,
which is how reconcile's `12 × 300s` reached ~61 minutes against a 90s default and
was SIGTERM'd while the server kept working. `budgets.quick_timeout_s` shipped
(read but absent from config); `MC_CONFIG` honoured by all four timer scripts;
`doctor.sh`'s `public_hosts` check anchored so the commented example no longer
satisfies it; `setup_spotify.sh` keeps credentials out of argv; `queue/.failed/`
ignored; dead `media.player` removed.

**Wrong-dated briefs**: `run_agent.py` gained `--date` and `--scheduled-at`, and a
run starting before the timer's own OnCalendar time is exactly a `Persistent=`
catch-up for yesterday — so the 00:42-on-the-30th case now writes the **07-29**
brief and *prints the correction* instead of silently re-dating. `Persistent=true`
kept: dropping it loses every brief for a box asleep at 07:30, which is the common
case here.

*Corrections to my brief:* `RestartSec=10` alone would **not** have fixed the
never-tripping restart loop (both 3s and 10s stay under the 5-per-10s burst) — the
explicit `StartLimitIntervalSec`/`StartLimitBurst` is what does it. And
`setup_spotify.sh` exposed the client **ID** in argv too, not only the secret.
`mission-tailscale-serve.service` was an unlisted instance of the timeout defect.

## HTTP coverage — and the bug it found

`tests/test_http.py`, **94 tests** where there were none: `POST /task` (divert wire
format, quick, agentic, trust boundary), cancel, the CSRF guard (including that a
rejected request creates **no task row**, i.e. the middleware really runs ahead of
the handler), `/events` driven against the ASGI app directly because `TestClient`
buffers and would hang forever, the lifespan's five background jobs, plus desktop /
media / automations / memory / stats / vault / learn.

**It caught a bug I introduced on 2026-08-08.** When I made `_settle_divert` derive
status from the executor, I left the HTTP renderer in `main.py` hardcoding
`"status": "done"` — so the two halves of one feature disagreed, and an unresolved
"put on something chill" was reported to an SSE client as a successful play with no
field to tell it apart. Fixed.

My first fix was too blunt and the agent's own test caught it: a **parked
confirmation** is not a failure over HTTP. There the caller is present, gets
`confirm_id`, and answers via the ConfirmBar or by voice — reporting 'failed' would
show an error for an ordinary "Shall I read your clipboard?". It settles 'failed'
on the queue/automation path only because nobody watches those sources. That
divergence is now deliberate, commented, and pinned by a test on both sides.
