# Session 26 — 2026-08-02: full-codebase review, then the fixes

User asked for a thorough senior-engineer review of the whole codebase, then

## What the review actually found

The architecture holds up — nothing here is a design problem. Three patterns
are worth naming because they're what kept the bug count low: deterministic
pre-checks in front of every model call (`spotify.detect` → `desktop.detect` →
`brief.is_quiet` → the inbox watcher), mechanical validation *after* every LLM
parse (the model picks words, Python picks behavior), and comments that record
the incident rather than restating the code.

**Almost every bug was in a seam between two subsystems that were each correct.**

## Fixed

1. **Deleting a file from `vault/inbox/` announced "Indexed 0 files"**
   (`inbox.py:141`). `step()` returns `(arrived, removed)` and the outer branch
   fires on either, but the notify branch only read `arrived` — so a removal
   took the `len(arrived) == 1` false path and formatted `0 files`. Directly
   contradicted the module's own docstring. Guarded on `arrived`.

2. **`/stats` `by_source.n` counted runs, not tasks** (`db.py:405`). `COUNT(*)`
   over `tasks LEFT JOIN runs` fans a task out across its attempts, so every
   refusal-fallback and resume-retry inflated it. On the real db, same window:
   **old 49, new 46** — 7 tasks have >1 run all-time. The dashboard reads
   `tasks_by_status` so it never showed, but the two totals in one response
   disagreed. `COUNT(DISTINCT t.id)`; the cost sum was already right.

3. **The diverts only existed in the HTTP handler** (`service.py`, `main.py`).
   `automations.fire` and `queue_watcher` call `svc.submit()` directly, so
   "every morning play jazz" correctly became a standing automation — and then
   handed **"play jazz" to Claude as a task every single morning** instead of to
   Spotify. Moved the whole divert chain to `Service.try_divert()`; `main.py`
   now renders it (byte-identical SSE, still no task row) and `submit()` uses it
   for `mode == "auto"`. Verified live: a fired automation reaches
   `spotify.run_intent`, spends **zero** model runs.
   - `submit()`'s callers need a task dict back, so a diverted command is
     recorded via `_settle_divert` as a task **born settled** — no run row (no
     model attempt to log, and `/stats` must not count one).
   - `task_type: "divert"` skips the notify gate (`notify.NEVER_GATE_TASK_TYPES`):
     the executor already wrote the one-line summary, and gating it would spend
     ~$0.04 rewriting a sentence we got for free. It is still *announced*.
   - Excluded from episode capture (`should_capture`) — same lesson as
     2026-08-02's daily-brief purge: only machine-submitted diverts get a task
     row, so capturing them would feed the graph an identical "play jazz"
     episode every morning forever.
   - **An automation can never create an automation** (`source != "automation"`
     guard). A `task_text` the parser left schedule words in would otherwise
     breed a fresh row on every fire.

4. **Desktop intents lowercased their arguments** (`desktop.py:210`).
   `_normalize` folds case before matching *and* the args were pulled from the
   folded string: `copy Hello World to my clipboard` → `hello world`, and
   `open youtube.com/watch?v=dQw4w9WgXcQ` → a **different video**. `_normalize`
   now takes `fold=`; matching still runs on the folded string, the four
   arg-bearing patterns run `re.I` against the case-preserving one.

5. **H2 was bypassed on the consolidation path** (`memory.py`).
   `AreaRegistry.agent_tools` strips Bash/unscoped-write from agent frontmatter;
   `build_consolidation` re-parsed that same file itself and didn't — and its
   metadata is submitted `trusted=True`, so it survived the H1 boundary intact.
   Simulated it: a reflection run (which holds `Edit(areas/**)`) writing
   `- Bash` into `areas/memory/agents/consolidate.md` handed the nightly
   consolidation a shell. Exactly the attack H2 exists for. Now routed through
   `AreaRegistry`, one source of truth for grants.

6. **`Origin: null` passed the CSRF guard** (`main.py:52`). `""` was in
   `_LOCAL_HOSTS` and `urlsplit("null").hostname` is `None` → `""`. The absent-
   Origin case is already handled by the `if origin` check, so `""` admitted
   nothing but the sandboxed-iframe header. Defence in depth — exploiting it
   needs a request simple enough to skip preflight, which a JSON body isn't.

7. **A dispatcher crash in `stream_quick` was filed as `cancelled`**
   (`service.py`). Client-disconnect and our-own-bug both landed in the same
   `finally`, so a DB error read as a user barge-in and stayed out of the
   success rate. `GeneratorExit`/`CancelledError` still settle cancelled;
   anything else settles **failed** and re-raises. The cleanup writes the task
   status *before* the run row and tolerates a failing DB — the first draft
   called the very method that had just thrown, and the test caught it.

8. **`ingest_vault` held vanished files in the index** (`ingest.py`). `seen.add`
   ran before `p.stat()`, so a file that disappeared mid-walk was marked seen
   and escaped the prune pass until a restart. stat first, then count.

## Reviewed and deliberately NOT changed

- **`metadata.task_type` / `metadata.agent` selecting a broader tool set.** I
  flagged this as a trust-boundary hole in the review and then **talked myself
  back out of it** — correctly, I think. Both select among *on-disk,
  operator-authored* manifests (config.yaml, `areas/*/agents/*.md`), which is
  the same trust level as SKILL.md, and the `agent` path is load-time sanitized
  and is exactly how the daily brief gets its grants (session 21's fix). Making
  either trusted-only would re-break the timers. The real residual is that the
  docstring's "can NARROW but never WIDEN" is imprecise: it's true of
  *caller-supplied* grants, not of selecting among operator-defined ones.
- **`simulate_refusal` from an untrusted caller.** `smoke_phase_a.sh` depends on
  it, and it grants nothing to someone who can already POST arbitrary tasks.
- **Quick-path concurrency is unbounded** (`self.sem` covers agentic only).
  Real, but a config decision, not a bug — left for the user.
- **Notices can strand in the voice loop** (`jarvis/main.py:320`): a notice
  arriving while Jarvis speaks *another notice* waits for the next user
  interaction, because `_flush_notices` only runs at the end of
  `handle_utterance`. Needs a restructure + hardware test; not done blind.
- **`degraded: true` is never surfaced in the UI.** The dispatcher sets it
  precisely so a client can label extractive answers; neither `CommandBox` nor
  `AskScreen` reads it. Worth doing — it's the one case where mislabeling
  matters most — but it's a feature, not a fix.
- **`ConfirmBar` never expires a pending row** client-side.

# Part 2 — cleanup pass (same session)

User then asked "what else to cleanup or change?" and approved the top four.

## Done

1. **A live `sk-ant-` API key was sitting in `.env` at the repo root.** 108
   chars, real shape. **Never committed** (`git log --all -- .env` empty, no
   `sk-ant-` anywhere in `git rev-list --all`), gitignored, and `cli_env` strips
   it from every subprocess — so it was defused, not leaking. But nothing reads
   it, the API path was deliberately removed 2026-07-27, and **`doctor.sh` had
   been warning about it** ("holds an API credential but nothing loads it").
   **Moved**, not deleted — it was the only copy — to
   `~/.local/share/mission-control/env.removed-from-repo-2026-08-02`, mode 600
   in a 700 dir. `.gitignore` entries kept as a guard. **The key should be
   rotated**: it lived in a working tree.

2. **`ui/dist/` was gitignored AND tracked — a rebuilt dashboard would not
   commit.** Proven, not assumed: dropping a fake `index-<hash>.js` into
   `ui/dist/assets/` left `git status` silent. Git keeps tracking existing
   files regardless of ignore rules, so it looks fine — but Vite emits
   content-hashed names, so after any UI edit the old asset shows as a deletion,
   `index.html` shows as modified pointing at the new hash, and **the new asset
   is invisible**. A fresh clone would get an `index.html` referencing a missing
   bundle. Removed the rule (the dispatcher serves this directory, so it must be
   committed); re-ran the same probe and the file now shows as `??`.

3. **Dead code from the Messages API removal**, confirmed by grep to have zero
   readers before touching anything: `Config.quick_cost()` (no callers), the
   `prices:` block (4 models, fed only quick_cost), the `models.classifier` key
   (never read — `classify()` is pure heuristic). Same class as
   `budgets.quick_max_tokens`, which session 25 removed. Left `llm_tiebreak` in
   place as a genuine injection point but rewrote its docstring, which still
   said "once API credentials exist".

4. **Tests for the three modules that had none.** `quick.py` was the important
   one: every existing test patches `dispatcher.service.quick.stream`, so
   `_stream_cli` — the code that parses the CLI's stream-json — had **zero**
   coverage, while its agentic sibling `runner._attempt` has had fake-process
   tests since Phase H. That is the highest-churn contract here (a CLI release
   changes the wire format, not our code). `tests/test_quick.py` (15) drives a
   fake process through partial deltas, the no-delta result path, garbage lines,
   refusal, the `errors[]`-only message a dead `--resume` produces, stderr on a
   missing result event, timeout-kills-proc, `procs[]` registration, and the
   flag contract incl. `--disallowedTools Bash`. `tests/test_bus.py` (9) pins
   EventBus drop-on-full + publish-stays-synchronous, and HookRegistry's
   exception isolation (the SSE broadcaster is the first hook — a later hook
   raising must not break task settlement).
