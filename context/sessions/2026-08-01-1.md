## The bug: a tolerable denial became a hard failure

`2026-07-30` daily brief settled **`failed`** having spent **$0.51**, error
"blocked by tool permissions — declared output file never written". The file was
fine. So was the run.

Three things had to line up:

1. **The Gmail grant never matched anything.** `areas/tasks/agents/daily-brief.md`
   asked for `mcp__gmail`; the connected server exposes
   `mcp__claude_ai_Gmail__*`. So every brief since Phase C requested Gmail, was
   denied, and burned a turn on it. Tolerable by design — the prompt said to skip
   the email section silently — so it stayed invisible.
2. **A catch-up run wrote the file early.** The box was off at 07:30 on 07-29;
   `Persistent=true` fired the brief at 00:42 **on the 30th**, by which point
   `{{DATE}}` was 2026-07-30. Hence no `2026-07-29.md`, and `2026-07-30.md`
   already existed and was correct.
3. **So the real 07-30 run made no edit** — correctly. But session 17's guard is
   an mtime test (`wrote_declared_output`), which cannot distinguish "a denial
   blocked the write" from "no edit was needed", and any denial + unchanged file
   → `failed`. Also hit **07-23**, so this was recurring, not a one-off.

Cost of the bug: a false failure, $0.51, and **no notify-gate run** that day
(failed tasks don't notify), so the silence looked normal.

### Fix

`runner.denial_could_block_output()` parses the tool name out of the denial text
and only counts `Write/Edit/MultiEdit/NotebookEdit/Bash` as able to explain a
missing file. An MCP or read tool can't write `vault/briefs/x.md`, so it no
longer promotes to failure. The promotion now runs off `blocking`, not `denied`.

**An unparseable denial stays fatal.** The dangerous direction here is the
session-17 one — reporting success while writing nothing — so unknown wording
fails loud.

+7 tests: read-only denial + unwritten output → `done`; **`Write` denial in the
CLI's real wording** + unwritten output → still `failed`; mixed denials fail on
the write one; and unit coverage of the parser incl. scoped grants
(`Edit(vault/briefs/**)`) and the unparseable-stays-fatal rule. The pre-existing
fixture's denial text has no "to use X" clause, so it exercises that path too.
