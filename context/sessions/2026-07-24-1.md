# Session 17 (2026-07-24): daily-brief regression — trust boundary starved the timers

Opened with "what should we do next?" → read STATE.md, then verified the claims
against live state instead of trusting them. Found a **live regression**: the
daily brief had silently written nothing on 2026-07-21/22/23 (three runs, all
settled `done`, ~$0.92 wasted) and would have broken the weekly review on Sun
07-26 the same way.

## Root cause (a self-inflicted wound from session 13)

Session-13 work-unit A added `sanitize_untrusted_metadata` (dispatcher/service.py:65):
any task from an external source has its `allowed_tools` metadata stripped —
correct, that's the H1 trust boundary. But `scripts/run_agent.py` (what every
systemd timer calls) submitted the agent's `Edit(vault/briefs/**)` grant *in
that same metadata key* over HTTP. Timers aren't trusted → the grant was
dropped → the brief agent fell back to the read-only baseline `[Read, Glob,
Grep]` → every `Write` was denied.

Second, compounding bug: **a run whose writes were all denied still reported
`success`**. The headless CLI surfaces a missing `--allowedTools` grant as an
ordinary `is_error` tool_result and lets the model continue; the model gave up,
explained itself in text, and the `result` line said success. Nothing surfaced
— no failed status, no notification. That's why it hid for three days.

## Fix (two parts, both landed + live-verified)

**1. Resolve agent tools server-side, not off the wire.**
- `dispatcher/areas.py`: new `AreaRegistry.agent_tools(area, agent)` reads
  `areas/<area>/agents/<agent>.md` frontmatter from disk and sanitizes it
  through the same `_sanitize_tools` as SKILL.md. Slug-guarded (`_SLUG_RE`)
  so a wire value can't traverse out of `agents/`.
- `dispatcher/service.py:_run_agentic_inner`: tool precedence now
  `meta.allowed_tools` (trusted spawns only) → **`areas.agent_tools(area,
  meta.agent)`** → area tools → task-type default.
- `scripts/run_agent.py`: sends `metadata.agent = <agent>` (a *reference*),
  no longer `allowed_tools` (a *grant*). The privilege manifest stays on-disk
  repo content — same trust level as SKILL.md — so this restores the grant
  WITHOUT reopening H1.

**2. Surface denied tools instead of reporting false success.**
- `dispatcher/runner.py`: `is_permission_denial()` + a `denied` flag on any
  `is_error` tool_result whose body matches the CLI's denial phrasing (flagged
  off the *full* text — a long path can push the tell-tale phrase past the
  200-char summary clip).
- Not every denial is fatal: the brief is written to skip its email section
  *silently* when Gmail MCP isn't granted, and still does its job. The fatal
  condition is a denial that stopped the run producing the file its prompt
  names. New `wrote_declared_output(text, root, since)` compares the declared
  output file's **mtime** to the run's wall-clock start (`wall_t0`, captured
  *before* spawn so a stale prior file can't vouch for an empty run). Denial +
  no fresh output → `failed` with a clear error; denial + output present →
  `done`, denial recorded in `result.denied_tools` and logged as a warning.
