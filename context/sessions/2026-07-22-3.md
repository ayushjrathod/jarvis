# Session 15 — 2026-07-22: hold-to-talk trigger for the assistant

## Request

"jarvis triggers when hey jarvis is said — I want an unused shortcut that,
while held, listens until let go, and does the same thing as hey jarvis."

## What was already there

`jarvis.main` has had a PTT path since Phase B (`--mode ptt|both`,
`start_ptt` → `HotkeyWatcher` → `Recorder` → the same `handle_utterance`).
It was dark for two reasons: `mission-jarvis.service` ran `--mode wake`, and
PTT keyed off `cfg.trigger_key` = F9, which mission-dictate owns. So this was
a wiring + key-allocation job, not new machinery.

## Changes

- `jarvis/config.py` — new `ptt_key` (default `KEY_RIGHTCTRL`, chosen by the
  user from four candidates: does nothing alone in almost every app) and
  `ptt_beep_ms` (90). `trigger_key` keeps its F9 meaning = dictation only.
- `jarvis/main.py` — `start_ptt` now watches `ptt_key`, warns if it equals
  `trigger_key`, beeps on press (880Hz) and release (660Hz), and treats a
  press during playback as an explicit barge-in (`player.stop()` →
  `speak_sentences` returns interrupted → `brain.cancel()`), so a new question
  isn't queued behind a long reply.
- `config.yaml` — `ptt_key`/`ptt_beep_ms` with the "must differ" comment.
- `systemd/mission-jarvis.service` — `--mode wake` → `--mode both` + comment.
- `tests/test_jarvis.py` — fixture carries `ptt_key`; defaults test pins
  `KEY_RIGHTCTRL`. 263 green.
- CLAUDE.md "Trigger layout" note rewritten (was: don't run ptt/both).

## Verification

Units reinstalled, `mission-jarvis` restarted: models warm in ~3s, log shows
`PTT ready: hold KEY_RIGHTCTRL to talk`, `mode=both`, and
`watching 4 keyboard(s) for 97`. Actual hold-speak-release is user-side (no
mic in this session).

## Notes / follow-ups

- Recorder opens its own `sd.InputStream` while the barge monitor may hold a
  `MicStream` — two concurrent capture streams. PipeWire handles it, but if
  press-during-reply ever misbehaves on hardware, that's the place to look.
- The press beep lands in the recording (async playback, recorder starts
  immediately). A 90ms tone is harmless to Whisper; delaying the recorder to
  dodge it would clip the first word, which is worse.
- Still uncommitted along with sessions 13/14 — same review-then-commit
  posture, including the `git add -f ui/dist/assets/...` caveat.
