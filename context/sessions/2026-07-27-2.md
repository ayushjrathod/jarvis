## 2. A real pre-existing bug, found by running the acceptance suite

`smoke_phase_a` came back **6/7**: the agentic task reported `failed` while the
smoke's "output file exists" check passed — misleading, because that file is
committed from an old run.

The cause is a permission grant that never worked. `task_types.summarize`
granted `Write(vault/**)`, and **a bare `Write(path)` rule is silently ignored
by this CLI** — the write is denied. Probed directly, outside the dispatcher:

| grant | result |
|---|---|
| `Write(vault/**)` alone | denied — "I need your permission to write to that file" |
| `+ Edit(vault/**)` | file written, **0 denials** |

Session 13 (M4) introduced the scoping; session 17's denial detection is what
finally surfaced it; the daily-brief agent already carried the correct form
**with a comment explaining it**, and the config simply never got the same
treatment. Fixed → **smoke_phase_a 7/7**.

The caveat was already in CLAUDE.md's "Known quirks" the whole time. Worth
remembering: a documented quirk is not a fix, and only running the acceptance
suite caught the gap between them.
