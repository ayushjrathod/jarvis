## Proposed design (key points)

### HTTP API (FastAPI, 127.0.0.1:8765)

- `POST /task` `{text, source, mode: auto|quick|agentic, area?, metadata?}` —
  single endpoint, response shape depends on classification:
  quick → SSE stream (`task`, `delta`, `done` events, one round trip for voice
  latency); agentic → `202 {task_id, status: queued, ack}`. Content-Type tells
  the client which path was taken.
- `GET /task/{id}` (task + all runs), `GET /tasks?status&kind&limit`,
  `POST /task/{id}/cancel` (barge-in + UI), `GET /events` (global lifecycle SSE),
  `GET /health`.
- Completion hooks = in-process callback registry; the SSE broadcaster is itself
  a hook. Jarvis subscribes to `/events` for spoken completion notices.
- Queue watcher: `queue/*.md`, YAML frontmatter (`mode`, `area`), body = task
  text; processed files moved to `queue/.processed/` with task-id suffix.

### SQLite (two tables)

- `tasks` (id uuid, created_at, source, kind, status, text, area, metadata JSON)
- `runs` (task_id FK, attempt, model, started/finished_at, status, stop_reason,
  cost_usd, tokens, num_turns, output_path, output_text, error, session_id)
- Refusal → run 1 `refused`, run 2 on fallback model; task keeps final status.
- Pragmas: WAL, synchronous=NORMAL, busy_timeout=5000, foreign_keys=ON.

### Voice ABCs (jarvis/plugins/base.py)

Four ABCs exactly: `WakeWordEngine` (load/process(frame)->bool/reset),
`STTEngine` (load/transcribe(audio)->str), `Brain` (async submit(text) ->
AsyncIterator[BrainEvent {ack|delta|done|notice|error}], async cancel()),
`TTSEngine` (load/synthesize(sentence)->Iterator[Frame]).
Frame = numpy int16 mono 16kHz. Playback + barge-in live in the player/main
loop, NOT in engines. Silero VAD is a fixed utility, not an ABC.

### Classifier

Heuristic first (question-shaped/short → quick; imperative + file/area refs →
agentic); ambiguous → one cheap Haiku call, forced one-word answer. `mode`
param overrides.

## Approval + implementation (same session, later)

User approved the Phase A design and git init (AskUserQuestion). User supplied
`ptt_dictate.py` — saved verbatim at `jarvis/ptt_dictate.py` (Phase B refactor).
Implemented the full dispatcher. **Deviations from the proposed design, with
reasons:**

1. **No `--max-turns`** — this claude CLI build (2.1.201) doesn't have the
   flag. Guardrails are `--allowedTools` + `--max-budget-usd` (native!) +
   wall-clock `timeout_s`.
2. **Quick backend is dual**: `messages_api` (locked decision #2) needs API
   credentials, but this machine has none (subscription OAuth only, no
   ANTHROPIC_API_KEY, no `ant` CLI). `quick_backend: auto` uses the Messages
   API when credentials appear, else `claude -p --output-format stream-json
   --include-partial-messages` (still streamed, works today). On the Messages
   API path with Fable 5, refusals are handled server-side via the
   `server-side-fallback-2026-06-01` beta + `fallbacks: [claude-opus-4-8]`;
   on the CLI path the dispatcher retries itself.
3. **Classifier is heuristic-only** — current rules leave no ambiguous bucket;
   `llm_tiebreak` hook exists for a Haiku call later (needs API creds anyway).
4. **Budgets**: a bare `claude -p` run carries ~$0.15–0.25 *notional* cost
   (system prompt overhead), so caps below that always trip
   `error_max_budget_usd`. Set quick=1.00, agentic=3.00.
5. **claude invocation**: the `claude` alias is zsh-only; dispatcher execs
   `/home/ayra/.local/bin/claude` with `CLAUDE_CONFIG_DIR=~/.claude-per`
   (both in config.yaml).

Key CLI facts learned: result JSON has `type/subtype/is_error/total_cost_usd/
usage/num_turns/session_id/result`; budget overrun → `subtype:
"error_max_budget_usd", is_error: true`; stream-json + `--include-partial-
messages` emits `stream_event` wrappers around Messages-API SSE events.
