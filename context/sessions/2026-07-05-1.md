## Proposed design (key points)

### HTTP API (FastAPI, 127.0.0.1:8765)

- `POST /task` `{text, source, mode: auto|quick|agentic, area?, metadata?}` —
  single endpoint, response shape depends on classification:
  quick → SSE stream (`task`, `delta`, `done` events, one round trip for voice
  latency); agentic → `202 {task_id, status: queued, ack}`. Content-Type tells
  the client which path was taken.
- `GET /task/{id}` (task + all runs), `GET /tasks?status&kind&limit`,
  `POST /task/{id}/cancel` (barge-in + UI), `GET /events` (global lifecycle SSE),
  `GET /health`.
- Completion hooks = in-process callback registry; the SSE broadcaster is itself
  a hook. Jarvis subscribes to `/events` for spoken completion notices.
- Queue watcher: `queue/*.md`, YAML frontmatter (`mode`, `area`), body = task
  text; processed files moved to `queue/.processed/` with task-id suffix.

### SQLite (two tables)

- `tasks` (id uuid, created_at, source, kind, status, text, area, metadata JSON)
- `runs` (task_id FK, attempt, model, started/finished_at, status, stop_reason,
  cost_usd, tokens, num_turns, output_path, output_text, error, session_id)
- Refusal → run 1 `refused`, run 2 on fallback model; task keeps final status.
- Pragmas: WAL, synchronous=NORMAL, busy_timeout=5000, foreign_keys=ON.

### Voice ABCs (jarvis/plugins/base.py)

Four ABCs exactly: `WakeWordEngine` (load/process(frame)->bool/reset),
`STTEngine` (load/transcribe(audio)->str), `Brain` (async submit(text) ->
AsyncIterator[BrainEvent {ack|delta|done|notice|error}], async cancel()),
`TTSEngine` (load/synthesize(sentence)->Iterator[Frame]).
Frame = numpy int16 mono 16kHz. Playback + barge-in live in the player/main
loop, NOT in engines. Silero VAD is a fixed utility, not an ABC.

### Classifier

Heuristic first (question-shaped/short → quick; imperative + file/area refs →
agentic); ambiguous → one cheap Haiku call, forced one-word answer. `mode`
param overrides.
