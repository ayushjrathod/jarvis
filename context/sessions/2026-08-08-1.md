User asked for a whole-codebase review with subagents, then to continue and fix
what it found. Six read-only reviewers (dispatch core / memory / actuators /
voice / UI+web / ops+tests) ran in parallel over the working tree — **including

## The headline: session 26's own fix introduced two of the worst bugs

Moving the deterministic diverts onto `Service.submit()` was right — a fired
"play jazz" automation really had been going to Claude every morning. But the
new `_settle_divert` path:

- **filed every divert `done`, including the ones that did not act.** A desktop
  verb parked for confirmation (nobody is watching the `queue`/`automation`
  source, so it expires after 120s), a denied verb, an unresolvable play, and —
  worst — `create_automation_from_nl` returning `(None, "Sorry…")`, which is the
  *normal* outcome during a plan-cap window because the parse is itself a quick
  task. The user's request was then neither scheduled, nor run, nor reported.
- **announced nothing.** It fires the plain `done` event with `kind="quick"`,
  and `brain_dispatcher.notices()` drops everything that isn't `kind ==
  "agentic"`; nothing on the path called `send_desktop`. Traced live: two events
  fired, both dropped. `notify.NEVER_GATE_TASK_TYPES` was unreachable dead code,
  and `test_deterministic_diverts_are_announced_but_never_gated` passed over a
  branch nothing could reach — it tested `surfacing()` directly.

Both fixed: `try_divert` now returns `ok` from the executor, a failed automation
parse **falls through to normal routing** instead of consuming the request, the
whole divert is wrapped so a crash can't 500 `POST /task` or send a queue file
to `.failed` as terminal, caller metadata (`automation_id`/`notify`) survives,
and delivery goes through `_deliver_notice` → the `notify` event every client
already speaks. `notify.surfacing`'s NEVER_GATE check moved *below* the
`notify: False` test, so "never gate" means that and not "always surface".

## Verified by execution, not by reading

### Degraded mode was dead (`offline.py`)
The relevance anchor called `db.search_entries(question, 1)`, and `fts_query`
joins terms with a space — FTS5 implicit **AND**. So it demanded every token,
stopwords included, in one chunk. Live index:

    'what is my preferred coding tool'  -> 0 hits
    'preferred coding tool'             -> 0 hits
    'Neovim'                            -> 1 hit

CLAUDE.md cites "preferred coding tool" as the proof this works — but that was
verified through `/memory/search`, which never applies the anchor. `_content_words()`
was computed and then never used for the query. Now probes per content word
(cap 8, `any()` short-circuits). End-to-end after the fix, real index:
those questions return 3 hits each (the USER.md Neovim block), while "the
airspeed velocity of an unladen swallow", "the tallest building in Dubai" and
"how do I reticulate splines" still return 0 — the property the anchor exists
for. `about`/`did` joined STOPWORDS: per-word anchoring means anything left in
the content list can anchor alone, and both match this index by themselves.
`tests/test_offline.py`'s fake DB ignored the query string entirely, so it could
not have caught this; rewritten to model AND semantics — **9 of 17 fail against
the pre-fix module.**

### The confirm plane was defeated by ordinary conversation (`desktop.py`)
`_YES_RE` used `\b`, not an end anchor, and `try_divert` consults
`parse_answer` on *every* utterance from a source with something parked:

    parse_answer('okay so what is the weather today') -> True
    parse_answer('sure, that makes sense')            -> True

So "what's on my clipboard" (parks, policy `confirm`) then "okay so what's on my
calendar" **read the clipboard** and swallowed the question. `clipboard_get` and
`open` are the only two verbs the confirm plane exists for. Now anchored `^…$`.

### `run the tests` was executed as an app launch (`desktop.py`)
`launch` policy is `allow`, so no confirmation — and since the diverts moved onto
`submit()` this ate queue files too and filed them `done`. Split into strong
verbs (`launch`/`open up`/`fire up`) and weak ones (`run`/`start`) whose argument
must pass a pure lexical `_looks_like_app_name()`.

While pinning that I found `open the door` → `Intent(launch, 'the door')` — and
checked it against HEAD before blaming the new code: **pre-existing**. The guard
was `len(target.split()) <= 3` and its comment claimed it stopped exactly this
string; "the door" is two words. Only the longer "open the door for the delivery
guy" was ever caught, which is why the existing prose test passed. Strong verbs
now use the same app-name test.

### `media-parse` was feeding the knowledge graph (`memory.py`)
Excluded from all three sibling hygiene lists but not `should_capture`. Live DB,
episode 62: the Spotify parser's own prompt template as `user_text`, its JSON
reply as `assistant_text`, `consolidated_at` set — the consolidation agent and
`graph-extract` had both already read a format instruction as "a day's
interaction with the user". Same mechanism as 5f200f3, one week later.
`inbox-summarize` added for the same reason (dormant). The exclusions are now
one `INTERNAL_TASK_TYPES` constant naming its siblings in a comment.

### The degraded answer was captured as an episode (`service.py`)
`answer = "".join(collected) or degraded` went straight into `_capture_episode`,
so the outage message got indexed — and the next question during the same outage
could match it and quote "Claude's session limit is hit right now…" back under
"here's what I already have on it". Capture now takes model output only.

### `simulate_refusal` was outside the trust boundary (`service.py`)
It forces a **second** run on `models.fallback` (an Opus). Verified: the
sanitizer stripped `allowed_tools`, clamped the budget, and passed
`simulate_refusal` through — so anything reaching `POST /task` (dashboard, phone
over Tailscale) could double the cost of every agentic run. Now stripped, with
`security.allow_simulate_refusal` (default **false**) as the opt-in
`scripts/smoke_phase_a.sh` needs; the script documents turning it on and back.

### The quick path ignored `metadata["allowed_tools"]` (`service.py`)
It derived tools from the matched area only. `inbox.summarize` ships
`["Read","Glob","Grep"]` with a prompt saying "Read it" — the grant was dead, so
it spent a real call per file on an answer the model could not ground, with
`--disallowedTools Bash` on top. Safe to honor because H1 strips the key
*before* storage, which is the same reasoning the agentic resolver already uses.

### `automations.detect` diverted questions (`automations.py`)
No wake-word strip and no `?` veto, unlike its two sibling parsers — and
`QUESTION_RE`/`STATEMENT_RE` are `^`-anchored, so one word in front defeated
them. The voice path splices the wake word onto every transcript, so in practice
they almost never fired. "hey jarvis, what do I have every morning?" cost a
parse call, created a standing automation that fires forever, and was never
answered. Added `_normalize` (looped politeness strip — real speech stacks
"please, can you …"), the `?` veto, `DESCRIPTION_RE` ("my gym schedule **is**
every monday"), and `RETROSPECTIVE_RE` ("every day **this week**").

### `inbox.summarize: true` was worse than useless (`inbox.py`)
Three defects at once: an `elif` meant it *replaced* the free "Indexed X" notice;
its result was delivered nowhere (source `inbox` isn't in `notify_sources`, so
the gate never runs, and the `done` event is `kind="quick"`); and the fan-out was
uncapped and serial on a directory the module's own docstring says the user
*syncs* into. Now additive, delivered via the `notify` event, capped by
`inbox.summarize_max_per_poll` (5) with the overflow logged **and named in the
notification**. Also `max(5, None)` on a blank `check_interval_s:` raised outside
the loop's try, on a task nobody awaits — the watcher just never started.

Plus VETO word boundaries in both `desktop.py` and `spotify.py` (`"open to"` ⊂
`"open toolbox"`, `"run out"` ⊂ `"run outlook"`, `"play out"` ⊂ `"play outkast"`
— all silently returned None), `_looks_musical`'s substring half
(`"band"` ⊂ `"abandoned"`), `policy:` fail-closed on a malformed config, the
smoke script's missing `ok()` (its advertised 7/7 was 7 of 8), and smoke cleanup.

## The UI batch (second half of the session)

All five web items fixed, `ui/dist` rebuilt and verified headlessly.

- **`sw.js` no longer poisons the installed app.** It stored *every* navigation
  response under cache key `"/"`, unconditionally — so one click on the
  dashboard's own "docs →" header link cached the docs page as the app shell,
  and behind Tailscale Serve a restarting dispatcher answers **502**, which
  *resolves* (so `.catch` never ran) and became the shell. Now `res.ok &&
  pathname === "/"` only, `waitUntil`-wrapped, `Response.error()` guard on the
  offline fallback (`respondWith(undefined)` rejects), cache name bumped to
  `-v2`, and hashed assets capped at 60 entries — `Cache.keys()` is specified to
  return insertion order, so trimming from the front evicts the oldest build.
- **SSE reconnects.** `subscribeEvents` had no `onerror` at all. EventSource
  retries a *dropped* connection itself but a non-2xx on reconnect is terminal —
  readyState goes CLOSED and nothing ever tries again, which is exactly what a
  dispatcher restart looks like through Serve. Capped backoff
  (1/2/5/10/30s), plus an `onStatus` callback driving a `.conn-banner`.
- **Widgets re-seed on reconnect.** They fetch from REST on mount and then only
  patch from events, so everything during an outage was invisible — a task that
  started and finished mid-restart stayed pinned "running" forever. `App`
  bumps an `epoch` on every *re*-connect (not the first) and the five seeding
  widgets depend on it.
- **Mic double-tap fixed** in both `CommandBox` and `AskScreen`: `recRef` is
  only assigned after the `getUserMedia` await while the button stays enabled,
  so two recorders started and the first was orphaned **with its tracks never
  stopped** — recording indicator lit, mic open until reload. Synchronous
  `startingRef` guard before the await.
- **Degraded answers are labelled, not thrown away.** Both surfaces branched on
  `status !== "done"` and rendered (and *spoke*) the raw CLI limit string while
  the real extractive answer sat right underneath. `res.degraded` and
  `res.speech` were read nowhere in `ui/src`.
- **New `Notices.jsx`** renders `notify` events — the notify gate's verdicts,
  inbox arrivals, and now diverts. They were subscribed in `api.js` and rendered
  nowhere; on the box `notify-send` masked it, but on the phone the entire
  proactive-notification feature was invisible.
- Also removed `App`'s dead `eventLog` (no widget read it; it re-rendered all
  six cards on every event).

**Verification** — chromium + CDP, cache disabled, cache-busting query, waiting
on explicit DOM conditions (the documented method):

## Not fixed — the standing list

Reviewed, real, and deliberately left. Ranked by what I'd take next.

state-changing methods, by `Origin`), so DNS rebinding makes `/vault/brief`,
