# Session 6 — 2026-07-10 (2)

## Dashboard horizontal-overflow fix

User report: dashboard content runs off the right edge of the screen instead
of wrapping. Two root causes, both in `ui/src/styles.css`:

1. `.grid` used `1fr 1fr` columns — grid items have implicit `min-width: auto`,
   so a card can never shrink below its widest content and long lines push the
   column past the viewport. Fixed with `minmax(0, 1fr)` columns plus
   `min-width: 0` on `.card`.
2. `pre.brief` and `.answer` had `white-space: pre-wrap` but nothing breaking
   long unbroken tokens (URLs/paths in briefs and answers). Added
   `overflow-wrap: anywhere` to both.

Rebuilt `ui/dist` (`npm run build`); confirmed the running dispatcher serves
the new CSS (StaticFiles reads from disk — no restart needed). Browser
hard-refresh picks it up.

Files touched: `ui/src/styles.css` (+ regenerated `ui/dist`).

## Agent activity rows: click-to-expand toggle

toggles an expanded detail panel. `ui/src/widgets/AgentMonitor.jsx`: the row is

is a Set of task_ids so multiple rows can be open. The panel shows the full
task text (wrapped) plus task id, source, area, created time, and — when the
SSE event carried them — model, cost, and error. Rows seeded from `/tasks` now
also keep `area`/`created_at`. Detail styles in `styles.css` (`.row`, `.detail`
dl grid, caret indicator).

Verified via CDP (node 22 built-in WebSocket driving system chromium — no new
deps; script in scratchpad): 15 rows rendered, click → detail panel +
aria-expanded=true, second click → collapsed, and zero horizontal overflow
while expanded. `--dump-dom` alone doesn't work here: the SSE `/events`
stream keeps the page loading forever, so the dump fires before fetches
resolve — use CDP for any future dashboard verification.
