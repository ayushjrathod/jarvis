# Session 2026-07-24 (2) — phone access via Tailscale + installable PWA

Implemented the phone-access plan from `future/phone-access-and-feature-gaps.md`.

## Decisions (asked the user up front)

The doc left the choice open and it changes what gets built, so I asked:

- **Access option → Tailscale.** Private mesh, no token-auth code, no public
  port, works off home wifi. (LAN-only was cheapest but home-wifi-only;

  the doc's stated reason to avoid it.)
- **PWA manifest → yes**, rides along.

## What I built

### Origin guard trusts a configurable front-door host (the only real code)

`dispatcher/main.py`'s `guard_origin`/`_origin_is_local` is a **CSRF guard, not
authentication** — it 403s a state-changing request with a *non-local* `Origin`.
The dashboard loaded over `https://<box>.<tailnet>.ts.net` sends its own POSTs
with that Origin, so it would be rejected. Added:

- `config.yaml` `dispatcher.security.public_hosts` (string or list) — commented
  as the origin allowlist only, NOT auth; Tailscale is the access control.
- `Config.public_hosts` property (`dispatcher/config.py`) normalizing str→list.
- `_origin_is_local(origin, extra_hosts=())` now takes an iterable; middleware
  passes `(cfg.host, *cfg.public_hosts)`. Loopback set unchanged.
- Tests (`tests/test_ask_screen.py`): an allowlisted `public_hosts` origin POSTs
  through (200); a *different* cross-origin site still 403s. **334 tests green**
  (was 332).

Deliberately did **not** add token-auth middleware or touch the bind address —
that's only needed for the public-URL options the user didn't pick.

### Tailscale Serve unit + setup script (user-side; not testable here)

- `systemd/mission-tailscale-serve.service` — oneshot + RemainAfterExit,
  `tailscale serve --bg --https=443 http://127.0.0.1:8765`, ordered after
  tailscaled + the dispatcher. Dispatcher stays on loopback; Serve fronts HTTPS.
- `scripts/setup_tailscale.sh` — idempotent: enables tailscaled, `tailscale up`,
  `tailscale set --operator=$USER` (so `serve` needs no sudo), installs+enables
  the unit, and **prints the exact `public_hosts` config line** derived from the
  box's MagicDNS name (`tailscale status --json`). Fails helpfully if HTTPS certs
  aren't enabled in the admin console. `bash -n` clean; tailscale isn't installed
  on this box, so the live run is the user's.
- `systemd/install.sh` gained a one-line pointer to the setup script (the unit is
  already copied by its `mission-*.service` glob, just not auto-enabled).

### Installable PWA (shipped, live-verified served)

- `ui/public/manifest.webmanifest` (standalone, theme `#0f1115`, any+maskable
  icons, /ask + /system-docs shortcuts).
- `ui/public/sw.js` — **minimal on purpose**: this is a live SSE dashboard, so
  the worker only makes the app installable + caches the shell and hashed
  `/assets/`; it never intercepts `/events` or any POST/API GET (only same-origin
  GETs for navigations/assets; network-first for navigations).
- Icons via PIL (`ui/public/icon-{192,512}.png`, `icon-maskable-512.png`,
  `apple-touch-icon.png`, `favicon.png`) — dark rounded "MC" tile matching the
  dashboard accent `#6ea8fe`. Visually checked the 192.
- `ui/index.html` — manifest link, theme-color, apple-touch-icon + apple
  standalone meta, `viewport-fit=cover`.
- `ui/src/main.jsx` — registers `/sw.js` on load (guarded; harmless on loopback).
- `dispatcher/main.py` — defensive `mimetypes.add_type("application/manifest+json",
  ".webmanifest")` (this Python's stdlib already knows it; belt for older ones).
  No new dispatcher routes — StaticFiles at `/` serves everything in `ui/public/`
  after build.
- `npm run build` clean; `ui/dist` rebuilt (new JS `index-BsED9CnX.js`, CSS hash
  unchanged).

## User-side (nothing here can do it)

`sudo pacman -S tailscale` → `scripts/setup_tailscale.sh` → paste the printed
`public_hosts` line into config.yaml → `systemctl --user restart
mission-dispatcher` → install Tailscale on the phone, join the tailnet, open the
URL, add to home screen (installs the PWA).
